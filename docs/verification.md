# Verifying a bundle

`lib-agent-prompt` produces a signed OCI artifact. Downstream consumers verify
it at build time (Dockerfile) or runtime (sandbox handshake) using `pkg/verify`.

## Supply-chain verification

`pkg/verify` shells out to cosign for keyless signature verification (existing).
GPG tag verification on the source release tag is also supported. SLSA L3
provenance is generated by the release workflow.

## Structural verification

```go
import "github.com/lee-mcfaul2/lib-agent-prompt/pkg/verify"

if err := verify.VerifyBundleStructure(bundleRoot); err != nil {
    // bundle is malformed
}
```

`VerifyBundleStructure` checks that the expected envelope schemas
(`user-prompt`, `final-response`, `tool-result`), the manifest, and the
shared schemas exist, and that every per-tool MCP entry has both
`.request.json` and `.response.json`.

## Instance validation

```go
// Validate a user-prompt payload against the bundle's user-prompt schema.
verify.VerifyUserPrompt(bundleRoot, rawInstance)

// Validate a tool-call args payload.
verify.VerifyToolRequest(bundleRoot, "customer", "search_customer", argsJSON)

// Validate a tool-call response payload.
verify.VerifyToolResponse(bundleRoot, "customer", "search_customer", responseJSON)
```

These are the same JSON Schema rules the gateway enforces inline; calling them
from a consumer is a defense-in-depth pattern (see `agent-sandbox` for an
example).
